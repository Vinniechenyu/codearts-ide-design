换形态之前，先把 IDE 的三个隐含前提换掉

常见归因是「工具属性太重」。这个归因不够精确——按它推导，只会做出一个 IDE 阉割版，两头不靠。

真实原因是 IDE 的价值单元是代码库，并隐含三个前提：你有仓库、你自备运行环境、你自己定义「做完了」。全民用户三个都不具备。

结论 码道 Work 不是 IDE 的简化版，而是同一套 Agent 工程化能力，换一个价值单元重新封装——这也是它能与 IDE 共存而不互斥的原因。

DESIGN POINT 4.1

不让用户配流程
让成功的交付自己变成流程

自动化必须由一次已成功的真实交付反向生成，而不是让用户先画流程图——正向配置是全民用户的第一道劝退门。

采纳即询问，一次点击存活
系统自动推断活名、输入契约、产物模板与搭档配置，用户只需确认。
参数不超过五项
只暴露「每次会变」的输入；其余沿用上次口径并标注可改。
触发后不自动交付
定时到点只产出到「待你确认」，是否发出永远由用户决定。

多任务主状态仲裁顺序
1P0 高风险权限或不可逆决策 · 必须由用户立即判断
2P1 等待用户补充或方向选择 · 任务已经停止推进
3失败且无法自动恢复 · 需要用户选择恢复路径
4已完成且尚未查看 · 有成果等待交付
5执行中 · 正常后台工作
6规划中 · 正在形成目标与路径
7接收中 · 正在接收输入
8已暂停 · 保留但不推进
9待命 · 无当前任务
离线特例离线不是固定优先级：全部任务停止才显示离线；单个连接器离线则作为相关任务的失败/需要你的原因；不用离线覆盖一个更紧急且仍可处理的本地权限请求
桌面权限气泡规则
低风险 · 可逆 · 本地桌面可「允许一次 / 拒绝」，但必须显示具体对象与范围
中风险 · 影响外部系统只提供「查看差异 / 打开完整授权」，不在小气泡盲批
高风险 · 不可逆 · 敏感数据仅提供「查看并处理」，必须进入 Work 完整上下文
批量或持久授权仅进入设置 / 授权中心，明确范围、期限与撤销方式
单一决策面（不得双入口）
口径决策状态由 Work 权限系统统一创建，桌宠只是该决策的桌面呈现；任一入口处理后其他入口立即同步；「始终允许」必须写明范围、时长与撤销入口
免打扰降级
全屏 / 演示 / 会议进入迷你模式；P2/P3 不弹气泡；P0/P1 只保留稳定标记，退出后再展开
运行时能力「减少动态效果」必须是运行时一级能力，不是主题自愿支持；关闭桌宠后任务仍在 Work 正常运行

口径这七项任一超阈值即阻止发版，与"好不好看"无关。度量口径：任何非任务事件驱动的状态改写都必须带枚举 reason（进程退出 / 会话超时 / 忙碌超时 / 连接不可达…）并写进可追溯记录，按 reason 分组统计即为误报与幽灵运行的直接测度。另需补一条：忙碌态必须有过期时间，超时降级为待命——忙碌态有过期，空闲态没有
五个可量化的验证假设
H1 降监控成本用户是否减少反复打开 Work 查看进度 → 后台任务期间 Work 无效回访次数
H2 介入更及时权限与决策是否更快被处理 → 决策等待时长、处理完成率

H4 证据胜过庆祝用户是否相信结果已可用 → 完成误报率、首次验收通过率

这意味着 · WHAT IT IMPLIES
为了准确表达失败，可以牺牲可爱。
为了突出成果，可以让角色退到背景。
为了长期安静，可以减少人格动作。
为了用户控制，可以打断顺滑的自动执行。
不能为了品牌识别，让所有状态持续使用强品牌色。
